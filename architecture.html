QCS Oracle Automation Architecture

QCS turns natural-language Oracle EBS R12 test instructions into generated pytest replay scripts for mixed OAF/web and Java Forms workflows. AI is allowed during recording and failure healing only. Normal replay is deterministic and resolves user-friendly script references through the object repository, Playwright, and the local Java Forms agent. A companion web studio lets a human scan a live Forms window and curate the element repository the scripts depend on.

Record Once

AI watches screenshots, decides the next action, and the recorder stores structured actions in recording.jsonl.

Replay Often

Generated pytest scripts call a readable DSL and run without any LLM calls in the normal path.

Repo Resolves

Business names map to Java-agent and Playwright descriptors in repo/repo.db.

Studio Curates

The web studio scans forms, overlays elements on a screenshot, and lets a human build reusable containers.

Quick Start For Developers

The two local loops: the CLI record/replay pipeline, and the web studio for repository curation.

Record, Generate, Replay

python -m qcs record instructions.txt --run-id rec_014 --auto-name
python -m pytest generated_tests\rec_014 -q -s

Recording writes recordings/rec_014/recording.jsonl, a validated recording.manifest.json, diagnostics, repo updates, regenerated page objects, and generated_tests/rec_014/test_rec_014.py. Replay logs in, opens the form, attaches the Java agent, and runs deterministic actions. Use qcs gen validate before committing a suite.

Run The Web Studio

python -m qcs_studio                 # FastAPI backend (:8090)
cd qcs_studio\web
npm install
npm run dev                          # React frontend (:5176, proxies /api)

Pick a running Oracle Java window, scan it, review the screenshot with its element overlay, drag discovery elements into the tree, then save the curated container into the repository.

QCS Studio — Web Repository Builder

qcs_studio/ is a local FastAPI backend serving a React + TypeScript (Vite) frontend. It scans a live Oracle Forms window through the same Java agent, then lets a human review and curate the element repository visually. It runs a two-phase scan so capture stays fast and tree-building can be retried without touching the live window.

Backend API (/api/v1)

  • GET /windows — list running Oracle Java processes.
  • POST /scan — Phase 1: attach, capture raw DOM + screenshot (multi-tab DFS), return a ScanBundle with an empty tree.
  • POST /scan/recalculate — Phase 2: build tree + AI snapshot + hover overlay from the cached DOM; auto-dump artifacts.
  • POST /scan/save — persist a draft as an active container.
  • GET /scans/{id}/screenshot — screenshot (supports ?tab=).
  • GET /containers · /drafts · /drafts/{id} — list / inspect / delete.
  • GET/PUT /containers/{ref}, PUT …/display-tree — load / update / persist the curated tree.
  • PATCH/DELETE …/elements/{ref} — edit / remove one element.

Frontend (web/src/App.tsx)

  • Renders the screenshot with an overlay of element bounding boxes (sorted smallest-on-top).
  • Hover-to-highlight with a details tooltip: element_ref, name, type, role, value, actions.
  • Two hover modes — tree (curated only) and all (every scanned element).
  • Drag-to-add: "discovery" elements not yet in the tree are dragged onto tree nodes (addElementToNode), persisted via PUT …/display-tree.
  • Zoom / fit, expandable tree, per-tab screenshots.

Today the studio operates on a captured screenshot + overlay — there is no live cursor picking on the real Forms window yet, and no WebSocket. See Studio Enhancement: Live Element Picker.

Auto-Dump Rule

Phase 2 (compute_tree) writes tests/testdata/aisnapshot/new/<YYYYMMDD_HHMMSS>/ with ai_snapshot.txt, java_scan_dump.json, and screenshot.png (plus per-tab files for multi-tab forms). A human moves liked scans to approved/ to join the snapshot regression suite (test_aisnapshot_regression.py).

Current Module Map

Keep changes inside the layer that owns the behavior. Generated files are useful to inspect, but lasting fixes belong in the generator, repo, recorder, replay runtime, or studio.

CLI

qcs/__main__.py owns commands: record, play, normalize, gen run/gen validate, pages/flows, aliases validate/report, repo validate/repo-capture, center, agent.

Recorder

oracle_ai_agent owns AI-guided recording. tools.py exposes the model tool surface and writes recording.jsonl; play.py is screenshot-only computer-use. AI sees screenshots; Java DOM mapping stays local.

Java Forms Agent

java-agent/ (in-JVM, Attach API) and qcs_java_agent (Python client) extract, inspect, and replay Java Forms. Commands: scan, raw, layout, tables, click, settext, clear, presskey, screenshot, highlight, elementat.

Object Repository

qcs_repo stores forms and elements in SQLite repo/repo.db (forms, elements, containers, container_elements, repo_entries) with YAML export/fallback. RepoEntry is keyed by (form_ref, element_ref). Recording stores only actioned elements.

Manifest

qcs_manifest defines RecordingManifest/RecordingManifestStep. Canonical step fields: step_id, intent, surface, action, form_ref, element_ref, input, assertions, diagnostics, metadata. No target_ref.

Generator

generator converts manifest steps into pytest suites using the FormReplay DSL. naming.py (sanitize_ref, AliasResolver) + alias_catalog.py (config/aliases/<domain>/<form_ref>.json) produce business-readable names. script_validator.py is the readability gate.

Replay Runtime

qcs_replay.script.OracleReplay exposes login, open_form, form(). dsl.py adds RepositoryResolver, FormReplay, BrowserReplayBackend, JavaFormsReplayBackend, ReplayLogger, typed exceptions. failure_bundle.py writes diagnostics on failure.

Web Studio

qcs_studio — FastAPI backend (service.py ScanBundle, two-phase scan, auto-dump) + React frontend (web/src/App.tsx: overlay, hover tooltip, drag-to-add tree). Scans and curates the repository visually.

Control Plane Prototype

qcs_center is an early FastAPI + SQLite job/agent service; qcs_agent long-polls it and shells out to qcs record. Evolve into full record/generate/replay/artifact orchestration.

Generated Script Contract

Users launch generated pytest scripts directly. The script reads like a business replay while carrying deterministic form_ref and element_ref values so runtime resolution stays stable.

What Users See

# conftest.py (auto-generated) — login and open_form live here
# oracle_replay fixture: logs in, calls open_form(url=...), yields replay

# test_update_po_number.py (auto-generated business steps)
from qcs_replay.script import OracleReplay

def test_update_po_number(oracle_replay: OracleReplay):
    order_type_lov = oracle_replay.form('order_type_lov')
    order_type_lov.set_text('order_type', 'CREDIT_ICO_TDS')
    order_type_lov.press_key('TAB')
    order_type_lov.click('find')

    confirm_dialog = oracle_replay.form('confirm_dialog')
    confirm_dialog.click('yes')

    order_summary = oracle_replay.form('order_summary')
    order_summary.click('open')

    purchase_order = oracle_replay.form('purchase_order')
    purchase_order.set_text('po_number', 'KRISHAN001')
    purchase_order.press_key('TAB')

What The Runtime Does

  • OracleReplay.login performs deterministic Playwright login with environment credentials.
  • OracleReplay.open_form navigates to RF.jsp, downloads JNLP, starts Forms, attaches the Java agent, and waits for readiness.
  • oracle_replay.form('form_ref') returns a FormReplay bound to the named form. Controls invoked from it: set_text, click, double_click, select_value, press_key, wait_for, assert_visible, assert_text, assert_value, get_text, get_value.
  • RepositoryResolver maps (form_ref, element_ref) to a descriptor and surface; a miss raises ReplayRefNotFoundError (no silent fallback). Surface routes by form_id prefix (html_ → browser, java_ → java_forms).
  • Technical Java IDs (java_*, _alt_*, toolbar\d) must never appear in generated step arguments. qcs gen validate enforces this.
  • Normal replay does not call an LLM. Healing opens only after a deterministic failure and produces a reviewable patch.

Oracle Forms Runtime

Java Forms automation is owned by the local Java agent. It attaches to the running Oracle Forms JVM via the Attach API and performs extraction and replay with structured component descriptors and screen-absolute bounds.

Non-Negotiable Forms Launch Rule

After Oracle EBS login succeeds, call oracle_form_open immediately. It handles responsibility selection and function navigation internally. If RF.jsp downloads a JNLP or starts Forms, call java_form_launch immediately before any Java Forms interaction.

AI Boundary And Healing

AI is an authoring and repair assistant, not the normal execution engine. Replay first tries deterministic repository resolution and Java/Playwright actions. Healing is two-tier and failure-only; the deterministic path never imports AI modules (guarded by test_replay_dsl_module_does_not_import_ai_modules).

Allowed AI

Recording, friendly-name proposals, failure healing, and patch suggestions.

Forbidden AI

Normal replay, ordinary locator resolution, data loading, assertions, and Java Forms execution.

Review Rule

AI-recorded and self-healed locator changes produce patches or reviewable repository changes — never silent merges.

Studio Enhancement: Live Element Picker Proposed

A planned upgrade to the studio: instead of curating from a static screenshot, the user clicks a button to enter a live pick mode, hovers directly over the running Oracle Forms window to see element details under the cursor, clicks to add that element to the component tree, and presses Esc (or a stop button) to exit back to the studio. The building blocks already exist in the Java agent — this is an integration, not new low-level capability.

Already available

elementat(x, y) deep hit-test, screenshot (screen or component), and highlight already ship in java-agent / JavaAgentDriver. Bounds are screen-absolute.

To add

A live-view transport (streamed frames or a native overlay), a throttled hover → elementat loop, a picker WebSocket, and studio state for the in-progress tree + an explicit exit.

Key decision

Fully web-based streamed-frame picker (no extension) vs a native transparent overlay helper driven from the web app. See the accompanying recommendation.

Team Development Rules

Put Changes In The Right Layer

  • Recorder behavior belongs in oracle_ai_agent.
  • Java Forms extraction/replay belongs in java-agent/ and qcs_java_agent.
  • Scan → tree / snapshot formatting belongs in qcs_java_agent/snapshot.py (re-approve baselines deliberately).
  • Repository identity, naming, and patch logic belongs in qcs_repo.
  • User-visible generated script behavior belongs in generator and qcs_replay.script.
  • Runtime locators, assertions, and healing belong in qcs_replay.
  • Web capture / tree curation / picker belongs in qcs_studio.
  • Fleet, jobs, artifacts, and UI APIs belong in qcs_center and qcs_agent.

Keep The System Safe

  • Do not add LLM calls to the normal replay path.
  • Do not send Java DOM to AI during normal recording; AI sees screenshots, local code maps coordinates.
  • Do not use screenshot clicking for normal Java Forms replay.
  • Do not navigate responsibilities or menus before oracle_form_open.
  • Tables group by recordIndex + columnKey metadata; do not reintroduce the removed Jaccard/geometry heuristic. Keep rows and buttons flat.
  • Do not serialize credentials or keys into prompts, recordings, logs, reports, generated tests, or DB rows.
  • Do not hand-edit generated tests, page objects, or flows for lasting fixes. Update the generator or repository source.
